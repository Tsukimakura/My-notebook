# 图片隐写 - Steghide

## 图像隐写术与 Steghide 技术原理综述

---

### 1. 图像隐写术基本概念

图像隐写术（Image Steganography）是一种将秘密信息隐藏在数字化图像载体中，且不引起第三方察觉的通信技术。与加密技术（Cryptography）改变信息内容使其不可读不同，隐写术侧重于隐藏“存在性”本身。

根据修改位置的不同，隐写术通常分为两大类：

- **空间域隐写（Spatial Domain）：** 直接修改像素点的颜色数值。最典型的例子是最低有效位（LSB）替换。

- **变换域隐写（Transform Domain）：** 在对图像进行离散余弦变换（DCT）、离散傅里叶变换（DFT）或离散小波变换（DWT）后，修改其频域系数。Steghide 针对 JPEG 格式的处理即属于此类。

---

### 2. Steghide 核心技术原理

Steghide 是一款开源的隐写工具，支持在 JPEG、BMP、WAV 及 AU 文件中隐藏数据。其核心竞争力在于通过复杂的算法平衡**嵌入容量**与**抗检测性**。

#### 2.1 基于图论的嵌入算法

Steghide 并不像基础工具那样按顺序修改像素。它采用了一种基于**图论（Graph-theoretic Approach）**的优化算法：

1. **构建匹配图：** 将图像中可以被修改的单元（如 JPEG 的 DCT 系数）视为图的节点。

2. **寻找最优替换：** 工具会寻找一种“交换”或“修改”方案，使得嵌入信息后，图像的统计特性（如颜色分布直方图）变化最小。

3. **最小化修改量：** 通过求解图中最大匹配问题，Steghide 能够仅通过改变极少量的系数值来完成大量数据的嵌入，从而规避简单的统计分析检测。

#### 2.2 离散余弦变换（DCT）域嵌入

针对 JPEG 格式，Steghide 操作的是 DCT 系数而非原始像素。JPEG 压缩过程如下：

$$
C_{u,v} = \alpha(u)\alpha(v) \sum_{x=0}^{7} \sum_{y=0}^{7} f(x,y) \cos\left[\frac{(2x+1)u\pi}{16}\right] \cos\left[\frac{(2y+1)v\pi}{16}\right]
$$

Steghide 在量化后的 DCT 系数中寻找不影响视觉质量的非零系数进行信息嵌入。这种方法比空间域隐写更具鲁棒性，因为即使图像经过轻微缩放或再次压缩，隐藏信息也有概率存活。

#### 2.3 安全与预处理流程

Steghide 在嵌入前会进行两道预处理：

- **数据压缩：** 默认使用 Zlib 压缩秘密信息，减小数据体积以降低载体变化率。

- **数据加密：** 强制要求输入密码（Passphrase）。系统使用该密码生成伪随机序列，决定信息的嵌入位置。即使隐写算法被识别，未经授权者也无法确定具体哪些位被修改或解密其内容。

### 3. Steghide 工具使用方法

Steghide 采用命令行交互方式，其基本操作分为“嵌入”与“提取”。

#### 3.1 核心命令参数

下表列出了常用的参数选项：

|**参数**|**全称**|**说明**|
|---|---|---|
|`-ef`|`--extractfile`|指定要隐藏的秘密文件路径|
|`-cf`|`--coverfile`|指定载体文件（如 jpg, bmp, wav）|
|`-sf`|`--stegofile`|指定生成的隐写文件路径（提取时指输入文件）|
|`-p`|`--passphrase`|命令行直接指定密码（不安全，建议手动输入）|
|`-v`|`--verbose`|显示详细处理信息|
|`-i`|`--info`|查看载体文件的隐写相关信息|

#### 3.2 常用操作流程

**1. 隐藏信息：**

执行以下命令将秘密文件 `secret.txt` 嵌入到图像 `source.jpg` 中：

`steghide embed -ef secret.txt -cf source.jpg -sf hidden_miao.jpg`

运行后系统会提示输入两次密码。

**2. 提取信息：**

从隐写图像 `hidden_miao.jpg` 中还原秘密文件：

`steghide extract -sf hidden_miao.jpg`

系统验证密码正确后，会将原始文件写入当前目录。

**3. 查看文件状态：**

在不知道密码的情况下，尝试探测载体是否包含 Steghide 隐写信息：

`steghide info miao.jpg`

该命令会显示文件格式、容量以及是否包含加密嵌入数据的可能性。

### 4. CTF Misc 场景中的辅助线索

在隐写类题目中，由于 Steghide 的安全性较高（暴力破解难度大），命题人通常会在以下位置留下获取密码（Key/Passphrase）的线索：

- **十六进制头/尾：** 使用 010 Editor 或 `hexdump` 观察文件，密码可能以 `key:` 或 `password:` 字样明文出现在图像元数据区域。

- **Exif 信息：** 通过 `exiftool` 查看图片的备注（Comment）或艺术家（Artist）字段。

- **源码注释：** 在网页题目的 HTML 源代码或 CSS 注释中隐藏。

- **LSB 预处理：** 有时密码本身也需要通过 StegSolve 的 LSB 提取功能先获取。

一旦获取密码并结合题目中“Hide”等暗示词汇，即可确定使用 Steghide 进行提取操作。
