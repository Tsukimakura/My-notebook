这里每次 `esi+24` 自增，然后存到 `eax` ，再和 `esi+28` 里的值比较。应该分别是当前已冷却时长和目标冷却时长。

用分析阳光一样的方法还原指针链：

结果搜不到…… 查了一下：

阳光（Sun）在属于“唯一实体”，主程序会用一个专门的指针一直指着它。但植物卡槽是一排列表（结构体数组）。程序只记录整个卡槽栏的基址，这个 `221D8460` 是 CPU 在运行这一帧时临时算出来的（没有保存再内存里）。

> `当前卡槽地址 (esi) = 卡槽栏基址 + (卡槽序号 × 单个卡槽的大小)`

既然如此就只能翻汇编来找了。先找卡槽栏的基址。

发现还能调试，这个函数里找不到基址，那看调用栈找一下父函数：

![[ctf101-reverse2-21.png]]

逻辑和结构体分析：

之前还刚好找到一个 UI 显示冷却的：

![[ctf101-reverse2-25.png]]

计算： $\frac{\text{MaxCD} - \text{CurrentCD}}{\text{MaxCD}}$

```text
inc [esi+24]             // 当前卡槽的冷却计时器 +1
mov eax, [esi+24]        // 读取当前冷却值
cmp eax, [esi+28]        // 与该植物的最大冷却值进行对比
jle 某地址               // 如果当前值 <= 最大值，直接跳过（保持冷却状态）

// 不满足跳转（冷却完毕）时执行的复位逻辑：
mov [esi+24], 00000000   // 当前冷却值清零
mov byte ptr [esi+49], 0 // 清除冷却中状态标志
mov byte ptr [esi+48], 1 // 设为 1，卡片亮起可种植
```

基于之前的分析，

`目标卡槽地址 (esi) = SeedBank基址 + (卡槽序号 × 0x50) + 0x28 (固定头部偏移)`

结构体基本还原成：

```cpp
// 单个植物卡槽的结构体 (总大小 0x50 / 80 字节)
struct SeedSlot {
    char pad_00[0x24];     // 0x00 - 0x23: 其他未知属性
    int currentCD;         // 0x24: 当前冷却时间
    int maxCD;             // 0x28: 最大冷却时间
    
    char pad_2C[0x1C];     // 0x2C - 0x47: 其他未知属性
    
    bool isReady;          // 0x48: 是否就绪 (1为可种植，0为冷却中)
    bool isCooling;        // 0x49: 是否处于冷却状态的关联标志
    
    char pad_4A[0x06];     // 0x4A - 0x4F: 补齐结构体到 0x50 字节
};

// 卡槽栏结构体
struct SeedBank {
    char pad_00[0x28];     // 0x00 - 0x27: 卡槽栏的头部属性
    
    // 0x28 起始位置：存放所有植物卡槽的数组
    SeedSlot slots[10];    // 数组中每个元素占用 0x50 字节
};

// 游戏主控板结构体
struct Board {
    char pad_00[0x15C];    // 0x00 - 0x15B
    SeedBank* pSeedBank;   // 0x15C: 指向 SeedBank 对象的指针
};
```
