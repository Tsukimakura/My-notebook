### 理解简单 RISC-V 程序

**1. `acc` 是如何获得函数参数的，又是如何返回函数返回值的？**

- 获取参数： 前两个参数 `a` 和 `b` 分别通过 **`a0`** 和 **`a1`** 寄存器获得。
    
- 返回返回值： 通过 **`a0`** 寄存器返回给调用者。在函数末尾的 `mv a0, a5` 指令把计算结果放入 `a0` 中。
    

**2. `acc` 函数中 `s0` 寄存器的作用是什么，为什么在函数入口处需要执行 `sd s0, 40(sp)` 这条指令，而在这条指令之后的 `addi s0, sp, 48` 这条指令的目的是什么？**

- `s0` 的作用： `s0` 被用作帧指针（栈底指针，相当于 x86 的 bp），指向当前栈帧的底部（高地址）。用于对局部变量、参数等寻址。
    
- 为什么执行 `sd s0, 40(sp)`： `s0` 在 RISC-V 约定中属于 Callee-saved Register。因为 `acc` 函数需要使用 `s0` 作为自己的帧指针，必须先将调用者的旧 `s0` 值保存到栈上，以便在函数返回前能够恢复，确保调用者环境不被破坏。
    
- 为什么执行 `addi s0, sp, 48`： 将当前的栈指针 `sp` 加上分配的 48 字节，赋值给 `s0`。就是当前栈底的位置。
    

**3. `acc` 函数的栈帧 (stack frame) 的大小是多少？**

- 48 字节， `addi sp, sp, -48` 。
    

**4. `acc` 函数栈帧中存储的值有哪些，它们分别存储在哪（相对于 `sp` 或 `s0` 来说）？**

栈帧中存储了调用者的 `s0`、函数的参数以及局部变量：

- **`40(sp)`** 或 **`-8(s0)`**：`s0`
    
- **`-24(s0)`** 或 **`24(sp)`**：`i`
    
- **`-32(s0)`** 或 **`16(sp)`**：`res`
    
- **`-40(s0)`** 或 **`8(sp)`**：`a`
    
- **`-48(s0)`** 或 **`0(sp)`**：`b`
    

**5. 请简要解释 `acc` 函数中的 `for` 循环是如何在汇编代码中实现的。**

1. 在进入循环之前，完成 `res = 0` 和 `i = a` 的操作，并将变量存入栈中。
    
2. 条件检查： 使用无条件跳转 `j .L2` 直接跳转到循环判断部分。
    
3. 条件判断`.L2`： 从栈中加载 `i` 和 `b`。使用 `ble a4, a5, .L3` 指令比较 `i` 和 `b`。如果满足条件 `i <= b`，跳转回 `.L3` 执行循环体。否则指令继续向下执行，从而退出循环。
    
4. 循环体执行`.L3`： 执行累加 `res += i` 和步进 `++i` 操作，并在每次操作后将更新后的变量写回栈。

**1. 请查阅资料简要描述编译选项 `-O0` 和 `-O2` 的区别。**

- `-O0`（无优化）： 
	
	- 较快的编译速度和较好的调试体验。
    
    - 特点： 严格遵循 C 语言的语义，逐行翻译。它会为每一个局部变量分配栈内存，每次计算从内存 `load` 到寄存器，算完再 `store` 回内存。因此执行速度最慢，代码体积最庞大。
        
- `-O2`（中高级优化）： 
	
	- 在不显著增加编译时间的前提下，追求极高的运行速度和较小的代码体积。
    
    - 特点： 编译器开启一系列优化算法（如数据流分析、寄存器分配、死代码消除、循环优化）。尽可能把所有变量用寄存器存储，避免缓慢的内存访问；会重写逻辑，利用硬件的最大性能。生成的汇编代码结构可能与 C 源码有很大差异，难以逐行调试。
        

**2. 请简要讨论 `src/lab5-1/acc_opt.s` 与 `src/lab5-1/acc_plain.s` 的优劣。**

- **`acc_plain.s` (`-O0`)**
    
    - 优： 逻辑清晰，汇编代码与 C 语言源码存在一一对应关系。可读性和可调试性强。
        
    - 劣： 性能差。
        
- **`acc_opt.s` (`-O2`)**
    
    - 优： 性能好（实现零内存访问）。
        
    - **劣：** 可读性和可调试性差。

### 理解递归汇编程序

**1. 为什么 `factor` 函数的入口处需要执行 `sd ra, 24(sp)`，而 `acc` 函数没有？**

- **原因：** `factor` 是一个非叶子函数， `acc` 是一个叶子函数。
    
- `factor` 内部包含了对自身的函数调用，执行 `call` 指令时，会把新的返回地址覆盖写入到 `ra` 寄存器中。如果不提前把最初进入该函数时的 `ra` 保存到栈上，当函数使用 `jr ra` 返回到更外层的调用者时，就会发生错误。
    

**2. 请解释在 `call factor` 前的 `mv a0, a5` 这条汇编指令的目的。**

- 准备传递给子函数的参数。
    
- 根据 RISC-V 的调用约定，函数的第一个整型参数必须存放在 **`a0`** 寄存器中。
    

**3. 请简要描述调用 `factor(10)` 时栈的变化情况；并回答栈最大内存占用是多少，发生在什么时候。**

- 栈的变化情况： 每发生一次函数调用，栈指针 `sp` 向下移动 32 字节，建立一个新的栈帧，并将当前层的 `ra`、`s0` 和参数 `n` 压入栈中。调用 `factor(10)` 时，调用 `factor(9)`，接着 `factor(8)`……一直深入，栈空间不断向下增长（嵌套叠加）。当递归到达底部的 `factor(0)` 开始逐层返回时，每返回一层，`sp` 就会向上移动 32 字节，释放该层的栈帧。
    
- 最大内存占用： 计算 `factor(10)` 一共需要调用 11 次函数（分别是 `n` 等于 10, 9, 8... 一直到 0）。每次调用分配 32 字节。
    
    最大占用： 11 × 32 = 352 字节。
    
- 发生时间： 栈内存占用达到最大值发生在最后一次递归调用 `factor(0)` ，返回前。
    

**4. 假设栈的大小为 4KB，请问 `factor(n)` 的参数 `n` 最大是多少？**

- 4KB = 4096 字节。
    
- 因为每一个栈帧固定消耗 32 字节，所以这个栈最多能够容纳的嵌套调用层数为：
    
    4096 / 32 = 128 层。
    
- 由于求值 `factor(n)` 会从 $n$ 一直调用到 $0$，总共会产生 $n + 1$ 层调用。
    
- 因此，最大调用层数 128 等于 $n + 1$，推导出参数 `n` 的最大值：
    
    $n_{max} = 127$

**1. 请简要描述 `src/lab5-1/factor_opt.s` 和 `src/lab5-1/factor_plain.s` 的区别。**

- `factor_plain.s` (`-O0`) 保留了源代码的递归语义，存在密集的内存访问和指令开销。
    
- `factor_opt.s` (`-O2`) 把递归转化为了迭代语义。函数调用发生，且运算全部通过寄存器进行，实现了零内存访问。
    

**2. 请从栈内存占用的角度比较两者的优劣。**

- `factor_plain.s`： 空间复杂度为 $O(N)$。栈的深度会随着 $N$ 线性增长。当 $N$ 较大时，容易耗尽栈空间，引发栈溢出。
    
- `factor_opt.s`： 空间复杂度为 $O(1)$。函数不分配栈帧空间，栈内存占用始终为 0 字节，安全高效。
    

**3. 请查阅_尾递归优化_的相关资料，解释编译器在生成 `src/lab5-1/factor_opt.s` 时做了什么优化，该优化的原理，以及什么时候能进行该优化。**

**尾递归优化原理：**

当一个函数中的递归调用是该函数执行的最后一个操作时被称为尾递归。

由于递归调用之后不再需要使用当前函数的局部变量或状态，因此当前函数的栈帧就可以被丢弃或重用，编译器可以直接转换为 `goto` 语句或循环，消除函数调用的开销。

**编译器所做的优化：**

1. 引入累加器，用寄存器运算取消每次的内存访问。
    
2. 把递归转化成循环。
    

**什么时候能进行该优化：**

1. 代码符合“尾递归”范式时，大多数现代编译器都能把它优化为循环。
    
2. 当开启中高级优化（如 `-O2`, `-O3`）时，若非尾递归操作是符合结合律和交换律的数学运算（如加法、乘法），编译器能自动推导引入累加器，重构为迭代结构进行优化。

**1. 请简述在 `src/lab5-1/switch.s` 中是如何实现 `switch` 语句的。**

`switch` 语句是通过带相对偏移量的间接跳转表来实现的：

1. 索引规范化与边界检查： 将输入的变量 `x` 减去 `switch` 中最小的 case 值（20），将其映射为从 0 开始的数组索引。然后利用无符号比较（`bgtu`）的特性，用一条指令完成了上限和下限的越界检查。若越界，直接跳转到 `default` 分支。
    
2. 跳转表查表： 将规范化后的索引乘以 4（通过左移 `slli` 实现），作为内存偏移量。将该偏移量加上存放在只读数据段（`.rodata`）中的跳转表基地址（`.L4`），从内存中加载对应的 `.word` 数据。
    
3. 计算绝对地址并跳转： CPU 取出该偏移量后，再与基地址相加得出最终的绝对地址，最后通过 `jr` 指令进行无条件间接跳转。
    

**2. 请简述用跳转表实现 `switch` 和用 `if-else` 实现 `switch` 的优劣，在什么时候应该采用跳转表，在什么时候应该采用 `if-else`。**

**跳转表的优劣：**

- 优势： 时间复杂度严格为 $O(1)$。无论 `switch` 有多少个 case 分支，程序只需要执行一次内存加载和一次间接跳转即可到达目标代码块，执行时间恒定。且因为消除了大量的条件分支跳转，对 CPU 的流水线和分支预测器更为友好。
    
- 劣势： 空间复杂度较高，需要在内存的只读数据段中维护一个连续的数组。如果 case 的跨度极大，会浪费大量的内存空间来填充 `default` 占位符。
    

**`if-else` 的优劣：**

- 优势： 空间占用极小。不需要在内存中额外开辟数组结构，完全依靠寄存器比对和 `pc` 寄存器偏移。可以适配任何跨度和分布的数值判断。
    
- 劣势： 时间复杂度为 $O(N)$。在最坏的情况下，程序必须按照顺序逐个比对每一个条件。过长的 `if-else` 链极易引发 CPU 的分支预测失败，导致流水线清空，造成较大的性能损失。
    

**应用场景：**

- 跳转表： 当 case 的数值分布相对密集时，由于所需的跳转表数组较小，空间浪费在可接受范围内，采用跳转表换取较高的执行效率。
    
- `if-else`： 当 case 的数值分布稀疏或跨度过大时，使用跳转表将导致创建一个很大却几乎全为空的数组。此时使用 `if-else`。

### 设计冒泡排序的汇编代码

**`src/lab5-1/bubble_sort.s`**

```riscv
.text
.globl  bubble_sort

bubble_sort:
    addi sp, sp, -16  # 开辟栈帧
    sd s0, 8(sp)     # 保存原栈底指针到栈上
    addi s0, sp, 16   # s0 保存当前栈底指针

    # a0 == arr, a1 = len
    li t0, 1
    ble a1, t0, .L_finish   # len <= 1 则已经有序，直接结束
    addi t1, a1, -1 # t1 = a1 - 1 是外层循环最大次数
    li t0, 0        # t0 是循环变量 i
.L_outer_loop:
    bge t0, t1, .L_finish  # i >= len - 1, 循环结束
    
    sub t2, t1, t0  # t2 = (len - 1) - i 是当前内层循环的循环次数
    li t3, 0        # t3 是内层循环变量
    mv t4, a0       # t4  是遍历指针，初始化为数组首指针

.L_inner_loop:
    bge t3, t2, .L_outer_next  # j >= len - 1 - i, 跳出内层循环

    ld t5, 0(t4)   # t5 = arr[j]
    ld t6, 8(t4)   # t6 = arr[j+1]

    ble t5, t6, .L_inner_next   # arr[j] <= arr[j+1] 不交换，continue

    sd t6, 0(t4)
    sd t5, 8(t4)  # 交换

.L_inner_next:
    addi t4, t4, 8  # 指向下一个元素
    addi t3, t3, 1  # j++
    j .L_inner_loop # 继续内层循环

.L_outer_next:
    addi t0, t0, 1  # i++
    j .L_outer_loop # 继续外层循环

.L_finish:
    ld s0, 8(sp) # 回复调用者的栈底指针
    addi sp, sp, 16  # 回收函数栈空间
    jr ra  # 返回
```

### 设计斐波那契数列的汇编代码

**`src/lab5-1/fibonacci_test.c`**

```riscv
.text
.globl  fibonacci

fibonacci:
    addi sp, sp, -32   # 开辟 32 字节空间
    sd ra, 24(sp)      # 保护返回地址 ra (递归是非叶子函数)
    sd s0, 16(sp)      # 保护 s0，用 s0 记录当前层的 n
    sd s1, 8(sp)       # 保护 s1，用 s1 记录 fibonacci(n-1) 的结果

    # if (n <= 1) return 1;
    li t0, 1           # 加载立即数 1 到 t0
    ble a0, t0, .L_base_case # 如果 n <= 1，跳转到 Base Case 处理分支

    mv s0, a0          # s0 = n

    # 计算 fibonacci(n-1)
    addi a0, s0, -1      # 传参 a0 = n - 1
    call fibonacci       # 递归调用 fibonacci(n-1)
    mv s1, a0          # s1 = fibonacci(n-1) 的结果

    # 计算 fibonacci(n-2)
    addi a0, s0, -2      # 传参 a0 = n - 2
    call fibonacci       # 递归调用 fibonacci(n-2)
                         # a0 = fibonacci(n-2)

    add     a0, s1, a0      # a0 = s1 (即 fib(n-1)) + a0 (即 fib(n-2))
                            # a0 是本层函数的返回值
    j       .L_return       # 准备返回

.L_base_case:
    li      a0, 1           # base case 返回值设为 1

.L_return:
    ld      ra, 24(sp)      # 恢复原返回地址
    ld      s0, 16(sp)      # 恢复调用者的 s0 寄存器
    ld      s1, 8(sp)       # 恢复调用者的 s1 寄存器
    addi    sp, sp, 32      # 回收 32 字节的栈空间
    jr      ra              # 根据恢复后的 ra 跳转返回
```
