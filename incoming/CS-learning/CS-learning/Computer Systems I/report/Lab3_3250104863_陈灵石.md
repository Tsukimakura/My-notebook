### 使用 enum 语法 FSM 设计

**FSM.sv**

```verilog
module FSM(
	input rstn,
	input clk,
	input a,
	input b,
	output [1:0] state
);

	// fill your code
	typedef enum logic [1:0] {S0, S1, S2, S3} fsm_state;
	fsm_state st;
	always@(posedge clk or negedge rstn) begin
		if(~rstn) begin
			st <= S0;
		end else begin
			case(st)
				S0: begin
					if(a) st <= S1;
					else st <= S0;
				end
				S1: begin
					if(a) st <= S2;
					else if(b) st <= S0;
					else st <= S1;
				end
				S2: begin
					if(a) st <= S3;
					else if(b) st <= S0;
					else st <= S2;
				end
				S3: st <= S3;
				default: st <= S0;
			endcase
		end
	end

	assign state = st;

endmodule
```

- `enum` 定义一个位宽是 2 位的枚举类型。

- 在时钟上升沿和 rstn 信号下降沿触发 always 块，内部使用 if-else 和 case 语句，根据状态图描述状态切换的逻辑。

- 最后把状态连接到输出

### 比较 `enum + case` 的编程范式和数组查表的编程范式之间的优劣

**1. enum + case 编程范式（行为级描述）**

- **优：**
    
    - **高可读性与可维护性：** 使用 `enum` 自定义枚举类型，能为状态自动分配位宽和二进制编码，避免了 `localparam` 的硬编码。状态字面量（如 S0, S1）使状态转移图与代码高度对应，逻辑清晰，易于阅读和手工修改。
    
    - **小规模较高效：** 对于常规的、小巧的状态机，Vivado 能自动将其映射为少数几个 LUT，生成的纯逻辑电路比较精简，延迟低。
    
- **劣：**
    
    - **大规模状态下的资源爆炸：** 状态机的输入输出极其庞大时，使用 `case` 语句综合出的组合逻辑网络会很庞大，占用大量 LUT 资源，使电路布局布线困难，还会导致关键路径变长，恶化时序。
        

**2. 数组查表编程范式（数据级描述）**

- **优：**
    
    - **超大型状态机性能更好：** 通过将真值表数据提前计算并写入 `.hex` 文件，再用 `$readmemh` 初始化为二维寄存器数组。综合时将其映射为 FPGA 内部的 Block RAM（BRAM）。BRAM 存储密度远超分布式 LUT，这种设计显著压缩大型 FSM 的电路面积，使复杂电路更加紧凑，从而获得更优的时序表现。
    
- **劣：**
    
    - **可读性极差且维护困难：** 状态转移逻辑被硬编码成了晦涩的十六进制数据（如 `02040886220cf402`），可读性差。
        
    - **依赖自动化工具：** 由于手工编写和核对 `.hex` 文件极易出错且工作量巨大，这种范式通常依赖外部脚本程序来自动化生成真值表文件。
        
    - **小规模存在资源浪费：** 如果状态机本来就不大，强行映射为 BRAM 会浪费块RAM资源，且在极小规模下时序收益不明显。

### 有限状态机设计问题分析

```verilog
    always@(posedge clk)begin
        if(~rstn) state <= 2'b01;
        else state[1:0] <= state[0:1];
    end
```

没问题，为您精简总结如下：

**存在的不足和原因**

- 语法错误：`state[0:1]` 非法，需改用位拼接 `{state[0], state[1]}`。
    
- 逻辑缺陷：缺乏非法状态自恢复机制（没有对 `00` 和 `11` 状态进行处理）。

设计时仅考虑了理想工作路径（`01` ⇌ `10`），未覆盖 2-bit 寄存器的全部 4 种状态，遗漏了 `default` 逻辑。

**电路不稳定的后果**

- 当遭遇电压波动、辐射或时序违例等物理干扰时，寄存器若意外跳入 `00` 或 `11`，将陷入无限循环（`00` 交换高低位仍是 `00`），永远卡死，需要手动复位。

### 利用 Cnt2num 实现 1234 的 BCD 码计数器

**Cnt.sv**

```verilog
module Cnt #(
	parameter BASE = 10,
	parameter INITIAL = 0
) (
	input en,
	input clk,
	input rstn,
	input low_co,
	input high_rst,
	output co,
	output reg [3:0] cnt
);

	// fill the code
	assign co = (cnt == BASE-1) && en && low_co;
	always @(posedge clk) begin
		if(~rstn) begin
			cnt <= INITIAL[3:0];
		end else if(high_rst) begin
			cnt <= 4'd0;
		end else if(en && low_co) begin
			if(cnt == BASE-1) begin
				cnt <= 4'd0;
			end else begin
				cnt <= cnt + 4'd1;
			end
		end
	end

endmodule
```

**Cnt2num.sv**

```verilog
module Cnt2num #(
	parameter BASE = 24,
	parameter INITIAL = 16
)(
	input en,
	input clk,
	input rstn,
	input high_rst,
	input low_co,
	output co,
	output [7:0] cnt
);
	localparam HIGH_BASE = 10;
	localparam LOW_BASE  = 10;
	localparam HIGH_INIT = INITIAL/10;
	localparam LOW_INIT  = INITIAL%10;
	localparam HIGH_CO   = (BASE-1)/10;
	localparam LOW_CO    = (BASE-1)%10;

	// fill the code
	wire carry;
	wire is_max;
	wire clear;
	assign is_max = (cnt[7:4] == HIGH_CO[3:0]) && (cnt[3:0] == LOW_CO[3:0]);
	assign clear = is_max && en && low_co;
	assign co = clear;

	Cnt #(
		.BASE(LOW_BASE),
		.INITIAL(LOW_INIT)
	) cnt_low (
		.en(en),
		.clk(clk),
		.rstn(rstn),
		.low_co(low_co),
		.high_rst(high_rst || clear),
		.co(carry),
		.cnt(cnt[3:0])
	);

	Cnt #(
		.BASE(HIGH_BASE),
		.INITIAL(HIGH_INIT)
	) cnt_high (
		.en(en),
		.clk(clk),
		.rstn(rstn),
		.low_co(carry),
		.high_rst(high_rst || clear),
		.co(),
		.cnt(cnt[7:4])
	);

endmodule
```

现有的 `Cnt2num` 模块内部包含了两个 `Cnt`，只能处理两位 BCD 码（最大模 100），需要级联两个 `Cnt2num` 模块来处理 4 位 BCD 码。

- 实例化两个 `Cnt2num`，低位模块处理 00~99，高位模块处理 00~12。将低位模块的 `co` 连接到高位模块的 `low_co`。

- 当计数器达到最大值 1233，并且低位仍有计数使能时，产生一个“全局清零”信号，将这个“全局清零”信号接入两个 `Cnt2num` 模块的 `high_rst` 引脚，使它们在下一时钟沿同时归零。

#### 预留 co、low_co、high_rst 引脚的意义

- **`low_co`：**
    
    - 决定了当前模块是否+1。
        
    - 不预留则所有的模块会在每个时钟周期同时累加。无法实现高位等待低位进位再加1的逻辑。
        
- **`co`：**
    
    - 向高位的模块产生进位，输入到高位模块的 `low_co`。
        
- **`high_rst`：**
    
    - 实现任意非标准模数，再达到特定取模条件下的最大树时所有模块全部复位。

**top.v**

```verilog
module top(
  input clk,
  input rstn,
  input [1:0] sw,
  input [0:0] btn,
  output [7:0] cs,
  output [7:0] an
);

  wire [31:0] clk_div;
  ClkDiv clkdiv(
    .clk(clk),
    .rstn(rstn),
    .clk_div(clk_div)
  );

  wire [1:0] btn_dbnc;
  Debouncer bd0(clk_div[10], btn[0], btn_dbnc[0]);
  wire next_test;
  PosSample sample0(clk, btn_dbnc[0], next_test);
  wire start;
  wire [31:0] multiplicand;
  wire [31:0] multiplier;
  DataGenerator data_generator(
    .clk(clk),
    .rstn(rstn),
    .next_test(next_test),
    .start(start),
    .multiplicand(multiplicand),
    .multiplier(multiplier)
  );

  wire [63:0] product;
  wire finish;
  Multiplier #(
      .LEN(32)
  ) mul (
      .clk(clk),
      .rst(~rstn),
      .multiplicand(multiplicand),
      .multiplier(multiplier),
      .start(start),
      .product(product),
      .finish(finish)
  );

  reg [63:0] product_reg;
  always@(posedge clk or negedge rstn)begin
    if(~rstn)begin
      product_reg <= 64'b0;
    end else if(finish)begin
      product_reg <= product;
    end
  end

  wire [31:0] data [3:0];
  assign data[0] = multiplicand;
  assign data[1] = multiplier;
  assign data[2] = product_reg[31:0];
  assign data[3] = product_reg[63:32];

  SegDriver segdriver(
    .clk(clk_div[10]),
    .rstn(rstn),
    .data(data[sw]),
    .point(1'b0),
    .LE(1'b0),
    .cs(cs),
    .an(an)
  );

```


#### 1. 仿真测试样例 (`testbench.v`)

通过阻塞等待语句直观实现：

- **发起请求：** `start = 1;`。
    
- **阻塞等待：** `wait(finish == 1);`。
    
- **确认并撤销：** 当乘法器算完拉高 `finish` 后，等待结束。主设备在下一个时钟沿 `start = 0;`，撤销请求，完成一次握手。
    

#### 2. 下板顶层结构 (`top.v`)

顶层结构通过使能寄存器实现了这套协议：

- 发起请求： 用户按下按键后，`DataGenerator` 生成一个 `start` 脉冲，触发乘法器进入工作状态。
    
- 数据捕获：
    
    ```verilog
    always@(posedge clk or negedge rstn)begin
        if(~rstn) product_reg <= 64'b0;
        else if(finish) product_reg <= product; // 只有 finish 为高，才“信任”并收下数据
    end
    ```
    
    顶层模块无视 `product` 的线上每个时钟周期的电平变化。只有当乘法器拉高 `finish` 时，顶层模块才把最终结果锁存下来。
    

#### 3. start-finish 协议存在的缺点

1. 缺乏反压机制，容易导致数据丢失。在这个协议中，只有主设备发起 `start`，从设备被动接受。

- 如果乘法器还在计算上一组数据（正处于 `WORK` 状态），此时主设备又产生了一个新的 `start`，会有 bug。

2. 阻塞式传输，吞吐量低。（“停等协议（Stop-and-Wait）”）。

- 主设备给出一个数据后，必须等 32 个时钟周期直到 `finish`，才能发送下一个数据。这根数据总线有大量时间是闲置的，造成硬件资源的浪费。
    

#### 4. 改进方法

采用 `valid-ready` 握手协议。

- 将 `start` 改名为 **`valid`**。
    
- 新增一个输出信号 **`ready`**。
    
- 将 `finish` 改名为 **`out_valid`**。
    

**改进后（双向握手）：**

1. 握手成功条件： 只有当 `valid == 1` 且 `ready == 1` 时，数据才算真正交接成功，乘法器开始计算。
    
2. **反压保护：** 当乘法器进入计算状态后，立刻拉低 `ready = 0`。此时主设备即使有新数据也不会传输给乘法器。

### 改进

**当前问题：** 无论乘数多大，状态机都循环 32 次。假如乘数是 `2`（二进制 `000...0010`），移位 2 次后，乘数区就全变成 0 了，后面的 30 次循环无用。

**修改方法：** 在 `WORK` 状态中，实时监控 `product_reg` 的低 32 位（即剩下的乘数）。如果它已经全为 0，说明计算已经提前结束，直接跳跃到 `FINAL` 状态。


**原代码片段：**

```verilog
	WORK: begin
		work_cnt <= work_cnt - 1'b1;
		if(work_cnt == '0) begin
			fsm_state_reg <= FINAL;
		end
		if(product_reg[0] == 1'b1) begin
			product_reg <= {adder, product_reg[LEN-1:1]};
		end else begin
			product_reg <= {1'b0, product_reg[PRODUCT_LEN-1:1]};
		end
	end
```

**代码修改片段：**

```verilog
	WORK: begin
		// 如果剩下的乘数位全是 0，说明已经没有需要累加的数了，提前结束。
		if (product_reg[LEN-1:0] == '0) begin
			fsm_state_reg <= FINAL;
		end else begin
			work_cnt <= work_cnt - 1'b1;
			if(work_cnt == '0) begin
				fsm_state_reg <= FINAL;
			end
			// 原本的移位累加逻辑保持不变
			if(product_reg[0] == 1'b1) begin
				product_reg <= {adder, product_reg[LEN-1:1]};
			end else begin
				product_reg <= {1'b0, product_reg[PRODUCT_LEN-1:1]};
			end
		end
	end
```
