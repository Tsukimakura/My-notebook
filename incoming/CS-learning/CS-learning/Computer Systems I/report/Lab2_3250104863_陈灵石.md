**adder.v**

```verilog
module Adder(
    input a,
    input b,
    input c_in,
    output s,
    output c_out
);
    //fill your code here
    wire p, g;
    assign p = a ^ b;
    assign g = a & b;
    assign s = p ^ c_in;
    assign c_out = p & c_in | g;
endmodule
```

**adders.v**

```verilog
module Adders #(
    parameter LENGTH = 32
)(
    input [LENGTH-1:0] a,
    input [LENGTH-1:0] b,
    input c_in,
    output [LENGTH-1:0] s,
    output c_out
);
    //fill your code here
    wire [LENGTH:0] c;
    assign c[0] = c_in;
    genvar i;
    generate
        for(i = 0; i < LENGTH; i = i +1) begin
            Adder adderi(.a(a[i]), .b(b[i]), .c_in(c[i]),
            .s(s[i]), .c_out(c[i+1]));
        end
    endgenerate
    assign c_out = c[LENGTH];
endmodule
```

利用 generate 和 for 循环简化代码，把每一位加法器的 `c_out` 和下一位的 `c_in` 相接，最后 `c_out` 为最高位输出的进位。整体构成行波进位加法器。

### 1. 关于 `$readmemh` 对一维向量数组的初始化

**观察结论：**

- **仿真环境：** `$readmemh` 会按行读取十六进制文件。文件中的第 $i$ 行数据会被赋值给数组的第 $i$ 个元素。如果文件中提供的十六进制数字符串对应的二进制位数小于向量宽度（64 bit），则**高位会自动补 0**。如果文件中行数少于数组深度，未被文件数据覆盖的数组元素在仿真中默认会初始化为 `x`（未知态）。
    

**`$readmemh` 初始化一维向量数组的规则总结：**

`$readmemh(文件路径, 数组名)` 通过读取十六进制文本文件，将数据按行的顺序逐个填入一维数组。对于数组中的每个 `bit`：

1. **映射关系：** 文件的一行对应数组的一个完整的一维向量元素。
    
2. **对齐与填充：** 每一个元素的赋值是从最低位（LSB）开始对齐的。十六进制数据会被展开为二进制，映射到对应 `[63:0]` 的比特位上；未被文本中十六进制数覆盖的高位比特将被赋予 `0`。

### 2. 超前进位加法器 (CLA) 和行波进位加法器 (RCA) 的优缺点比较

| **加法器类型**            | **优点**                                                                                                                        | **缺点**                                                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **行波进位加法器(RCA)**     | **1. 结构简单：** 直接由全加器级联而成，易于实现。<br><br>  <br><br>**2. 资源占用小：** 硬件面积与位宽 $N$ 呈线性关系（复杂度为 $O(N)$），功耗较低。                             | **1. 延迟极大：** 进位信号 $C_{out}$ 必须像波浪一样从最低位逐级传递到最高位，关键路径极长。<br><br>  <br><br>**2. 不适合高速运算：** 随着位宽 $N$ 增加，延迟成倍增加（延迟 $O(N)$），无法满足现代处理器的时钟频率要求。                 |
| **超前进位加法器(CLA)**<br> | **1. 速度极快：** 通过 $G$ 和 $P$ 信号，并行计算所有进位信号，打破了进位的串联依赖。<br><br>  <br><br>**2. 延迟低：** 理论上延迟时间与位宽无关或呈对数关系（复杂度 $O(\log N)$），适合高性能计算。 | **1. 结构复杂：** 随着位宽增加，计算进位的逻辑表达式会变得极长。<br><br>  <br><br>**2. 扇入/面积限制：** 高位的进位逻辑需要极大Fan-in，导致单级 CLA 很难做到高位宽（通常 4 位或 8 位为一单位），更宽的加法器需要采用多级树状结构，面积和功耗远大于 RCA。 |

### 3. 运算溢出的表示

#### **无符号数运算**

无符号数不关心符号位，只看最高位是否发生进位或借位。

1. **无符号加法**（`do_sub == 0`）：
    
    - **原理：** 如果相加结果超出了最大表示范围，最高位会产生向外的进位。
        
    - **表示：** $Overflow = c$ （即最高位产生的进位输出 $C_n$）。
        
2. **无符号减法**（`do_sub == 1`）：
    
    - **原理：** 减法在代码中被转换为补码加法：$a + \sim b + 1$。如果 $a \ge b$，相加后最高位必定会产生进位（$C_n = 1$），代表没有借位，结果正常。如果 $a < b$，则最高位不会进位（$C_n = 0$），这就意味着发生了借位，即下溢出。
        
    - **表示：** $Overflow = \sim c$ （进位输出取反）。
        

#### **有符号数运算

有符号数用补码表示，溢出发生在“两个同号数相加，结果符号相反时。
