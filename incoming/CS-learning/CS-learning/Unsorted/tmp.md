# C语言程序构建与底层原理学习笔记目录

## 第一章：C语言编译全景图 (The Compilation Pipeline)

1. **编译的四个核心阶段**
    
    - 预处理 (Preprocessing): 文本替换与头文件展开
        
    - 编译 (Compilation): 从C代码到汇编代码 (.s)
        
    - 汇编 (Assembly): 从汇编到机器码 (.o)
        
    - 链接 (Linking): 符号解析与地址重定位
        
2. **工具链操作指南 (GCC)**
    
    - 分步生成中间文件：-E, -S, -c 的使用
        
    - 多阶段输入灵活性：如何利用 .i, .s 跳级编译
        
    - 不同编译器对比：GCC vs Clang (LLVM) vs MSVC
        

## 第二章：编译的基本单位与预处理逻辑

1. **编译单元 (Compilation Unit)**
    
    - 定义：.c 源文件 + 递归展开的头文件
        
    - 独立性原则：编译器如何隔离处理每个编译单元
        
    - 作用域与可见性：static (内部链接) vs extern (外部链接)
        
2. **头文件管理**
    
    - 声明与定义的区别：为何声明可重复但定义不可重复
        
    - 头文件重复包含的危害：重定义错误与结构体冲突
        
    - 解决方案：头文件卫士 (Include Guards)
        
3. **头文件查找机制**
    
    - 双引号 "" vs 尖括号 <> 的查找优先级
        
    - 系统标准目录与 -I 参数的作用
        

## 第三章：底层基石——指令集架构 (ISA)

1. **ISA (Instruction Set Architecture) 概论**
    
    - 软硬件的契约：指令、寄存器、内存模型
        
    - 架构流派：CISC (x86) vs RISC (ARM/MIPS)
        
    - 架构 (Architecture) vs 微架构 (Micro-architecture)
        
2. **ISA 对编译的影响**
    
    - 编译阶段：如何决定指令选择与寄存器分配
        
    - 汇编阶段：二进制编码与字节序 (Endianness)
        
3. **编译器后端工作原理**
    
    - 目标元组 (Target Triple) 的作用
        
    - 中间代码 (IR) 到机器码的转化流程
        

## 第四章：中间产物——可重定位目标文件 (.o)

1. **核心概念**
    
    - 为何被称为“可重定位”：地址为0与符号留白
        
    - 文件格式标准：ELF (Linux) vs PE (Windows)
        
2. **内部结构解剖**
    
    - 代码段 (.text) 与 数据段 (.data)
        
    - 符号表 (Symbol Table)：导出与导入的符号清单
        
    - 重定位表 (Relocation Table)：给链接器的“施工说明书”
        

## 第五章：链接器的核心原理 (Linking)

1. **链接的三大步骤**
    
    - 段合并 (Section Merging)：拼图式组合
        
    - 符号解析 (Symbol Resolution)：全局符号表的匹配逻辑
        
    - 重定位 (Relocation)：绝对寻址与 PC相对寻址修正
        
2. **程序的真实入口**
    
    - main 函数不是第一步：_start 与 CRT (C Runtime)
        
3. **链接器查找机制**
    
    - 暴力轮询 (Linear Scan) 工作模式
        
    - 库文件内部结构：符号表 (nm 命令验证)
        
    - 为什么头文件不能替代库文件
        

## 第六章：库文件与工程实践

1. **静态库 (.a / .lib)**
    
    - 本质：.o 文件的归档包 (Archive)
        
    - 制作与使用：ar 命令与链接器的“按需提取”特性
        
2. **库的指定与查找**
    
    - 编译时查找：-L (路径) 与 -l (库名)
        
    - 运行时查找：RPATH, LD_LIBRARY_PATH, /etc/ld.so.conf
        
    - 依赖顺序陷阱：为何库文件必须写在被调用者后面
        
3. **特殊案例分析**
    
    - 数学库 (libm) 问题：为何有时不需要 -lm (GCC优化与内置函数)
        
    - G++ 驱动与 C 标准库的演变
