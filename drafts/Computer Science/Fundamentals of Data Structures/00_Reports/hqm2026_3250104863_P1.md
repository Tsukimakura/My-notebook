## Chapter 1:  Introduction

**Problem Description**

The objective of this project is to implement, measure, and analyze **the worst-case time complexities** of two search algorithms: **Sequential Search** and **Binary Search**. Both **iterative** and **recursive** versions are implemented.

To simulate the worst-case scenario, the algorithms search for a target value N within a sorted array containing elements from $0$ to $N-1$ (meaning the target is never found). Performance is measured using <time.h> across varying array sizes ($N\in\{100, 500, \dots, 10000\}$).

**Background of the Algorithms**

Sequential Search: A straightforward approach that scans the list from left to right, comparing each element with the target value. It does not require the dataset to be sorted.

Binary Search: A more efficient, divide-and-conquer algorithm that specifically operates on sorted arrays. It works by repeatedly dividing the search interval in half, comparing the target value to the middle element, and discarding the half where the target cannot possibly reside.

## Chapter 2:  Algorithm Specification

**ADT:** A normal list implemented by array.

**Pseudo-code of Algotithms:**

**Iterative Sequential Search**

```text
Algorithm I_Seq_Search(A, N, target):

    FOR i = 0 TO N - 1:

        IF A[i] == target THEN RETURN i

RETURN -1
```

**Recursive Sequential Search**

```text
Algorithm R_Seq_Search(A, N, target, index):

    IF index >= N THEN RETURN -1

    IF A[index] == target THEN RETURN index

RETURN R_Seq_Search(A, N, target, index + 1)
```

**Iterative Binary Search**

```text
Algorithm I_Bin_Search(A, N, target):

    left = 0, right = N - 1

    WHILE left <= right:

        mid = left + (right - left) / 2

        IF A[mid] == target THEN RETURN mid

        IF A[mid] < target THEN left = mid + 1

        ELSE right = mid - 1

RETURN -1
```

**Recursive Binary Search**

```text
Algorithm R_Bin_Search(A, target, left, right):

    IF left > right THEN RETURN -1

    mid = left + (right - left) / 2

    IF A[mid] == target THEN RETURN mid

    IF A[mid] < target THEN RETURN R_Bin_Search(A, target, mid + 1, right)

RETURN R_Bin_Search(A, target, left, mid - 1)
```

## Chapter 4: Analysis and Comments

### 4.1 Time Complexity Analysis (Worst-Case)

The worst-case scenario for all implemented search algorithms occurs when the target element is not present in the array (e.g., searching for $N$ in an array populated from $0$ to $N-1$).

- **Sequential Search (Iterative & Recursive):** Both versions must examine every single element in the array from beginning to end before concluding that the target does not exist. Therefore, the worst-case time complexity is **$O(N)$**. As $N$ grows, the execution time increases linearly, which is reflected in the testing data where $N=10000$ took significantly longer than smaller values.

- **Binary Search (Iterative & Recursive):**

    Because the array is strictly ordered, binary search eliminates half of the remaining search space with each comparison. In the worst case, the algorithm continues dividing the array until the sub-array size reaches $0$. The number of steps required is bounded by $\lfloor \log_2 N \rfloor + 1$. Thus, the worst-case time complexity is **$O(\log N)$**. The testing data clearly illustrates this, as the execution duration remained incredibly small and almost constant (at the clock's resolution limit) even when $N$ reached $10000$.

### 4.2 Space Complexity Analysis

Space complexity evaluates the extra memory required by the algorithm, excluding the input array itself. This is where the differences between iterative and recursive implementations become highly apparent.

- **Sequential Search (Iterative):** **$O(1)$**

    The iterative approach only requires a few local variables (such as a loop counter `i`). The memory footprint remains constant regardless of the input size $N$.

- **Sequential Search (Recursive):** **$O(N)$**

    Each recursive call pushes a new frame onto the system call stack containing local variables and return addresses. In the worst case, it will make $N$ nested recursive calls before hitting the base case. For very large values of $N$, this runs a severe risk of causing a **Stack Overflow**.

- **Binary Search (Iterative):** **$O(1)$**

    Similar to iterative sequential search, this method only uses a few local integer variables (`left`, `right`, `mid`) to track the search boundaries within a `while` loop, requiring strictly constant extra space.

- **Binary Search (Recursive):** **$O(\log N)$**

    The recursive binary search also consumes stack memory for each call. However, because the search space is halved each time, the maximum recursion depth is strictly bounded by $\log_2 N$. Even for exceptionally large datasets, the stack depth remains extremely small and safe (e.g., $N=1,000,000$ requires roughly 20 stack frames).

### 4.3 Comments on Further Possible Improvements

1. **Implementation Preference (Iterative vs. Recursive):**

    While recursion offers cleaner and more mathematically intuitive code, the iterative implementations are vastly superior for system performance. The testing results show that iterative sequential search runs slightly faster than its recursive counterpart due to the absence of function call overhead. Moving forward in C programming, iterative loops should be preferred for simple linear tasks to ensure memory safety ($O(1)$ space) and speed.

2. **Algorithm Selection:**

    The performance gap between $O(N)$ and $O(\log N)$ is massive at scale. If a dataset is known to be sorted, Binary Search should universally be utilized over Sequential Search.

3. **Testing Framework & Timer Resolution:**

	To achieve true microsecond-level profiling without running thousands of loops, future implementations could utilize hardware-specific CPU cycle counters (such as the `__rdtsc()` intrinsic in x86 architectures) or high-resolution POSIX timers like `clock_gettime(CLOCK_MONOTONIC, ...)`.
