# Protocols

## 一、 应用层 (Application Layer)

对应 OSI 模型的应用层、表示层、会话层（L5-L7）。直接面向业务提供服务，定义数据格式与交互逻辑。

|**协议名称**|**依赖传输层**|**默认端口**|**核心功能与技术特征**|
|---|---|---|---|
|**HTTP(S)**|TCP / UDP (HTTP/3)|80 / 443|**超文本传输(安全)协议。** 无状态请求/响应模型。HTTPS 在 HTTP 基础上结合 TLS 实现数据加密、完整性校验与身份认证。|
|**DNS**|UDP / TCP|53|**域名系统。** 将 FQDN（完全限定域名）解析为 IP 地址。常规查询使用 UDP，区域传送或响应截断时使用 TCP。|
|**SSH**|TCP|22|**安全外壳协议。** 提供加密的远程命令执行与隧道转发，替代非加密的 Telnet（端口 23）。|
|**FTP / SFTP**|TCP|20, 21 / 22|**文件传输协议。** FTP 使用双端口模式（21 控制，20 数据）。SFTP 则是基于 SSH 协议的安全文件传输子系统。|
|**SMTP**|TCP|25, 465, 587|**简单邮件传输协议。** 用于邮件的**发送**与服务器间的中继路由。|
|**POP3 / IMAP**|TCP|110, 995 / 143, 993|**邮件接收协议。** POP3 通常将邮件下载并从服务器删除；IMAP 支持双向同步，维护服务器端邮件状态。|
|**DHCP**|UDP|67 (S), 68 (C)|**动态主机配置协议。** 局域网内通过 DORA 广播过程（Discover, Offer, Request, Acknowledge）自动下发 IP、子网掩码、网关及 DNS 配置。|
|**SNMP**|UDP|161, 162|**简单网络管理协议。** 用于网络设备的监控与管理（161 轮询，162 Trap 告警）。|
|**BGP**|TCP|179|**边界网关协议。** 核心跨自治系统（AS）路由协议。虽基于 TCP 传输，但在网络架构中属于提供 L3 路由控制平面的应用。|

## 二、 传输层 (Transport Layer)

对应 OSI 模型的传输层（L4）。提供端到端的进程级通信及流量控制。

|**协议名称**|**核心机制**|**技术特性与适用场景**|
|---|---|---|
|**TCP**|面向连接、三次握手、四次挥手。|**传输控制协议。** 提供可靠交付、序列号排序、丢包重传、滑动窗口（流量控制）与拥塞控制。适用于对数据完整性要求极高的场景（Web、文件、邮件）。|
|**UDP**|无连接、即发即弃。|**用户数据报协议。** 不保证送达，不保证顺序，无拥塞控制，报文开销极小。适用于对延迟敏感、可容忍丢包的场景（实时音视频、DNS 查询、游戏状态同步）。|
|**QUIC**|基于 UDP 封装。|现代传输协议（HTTP/3 基础）。在 UDP 上实现 TCP 的可靠性，提供 0-RTT 握手、内置 TLS 加密，并解决 TCP 的队头阻塞（Head-of-line blocking）问题。|

## 三、 网络层 (Internet Layer)

对应 OSI 模型的网络层（L3）。负责逻辑寻址、路由选择与跨网段数据包转发。

| **协议名称**        | **核心功能与技术特征**                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| **IPv4 / IPv6** | **网际协议。** 无连接的数据报交付服务。IPv4 提供 32 位地址空间，IPv6 提供 128 位地址空间并内置 IPSec 支持，消除 NAT 依赖。网络层的所有数据均需封装在 IP 头部中。 |
| **ICMP**        | **互联网控制消息协议。** 封装在 IP 数据报中，无端口概念。用于网络层错误报告（如目标不可达、超时）与状态探查（如 Ping 的 Echo Request/Reply）。             |
| **IGMP**        | **互联网组管理协议。** 用于 IPv4 网络中管理组播（Multicast）组成员身份，支持一对多高效数据分发（如 IPTV 流媒体）。                               |
| **IPSec**       | **IP 安全架构。** 并非单一协议，而是一套体系（包含 AH、ESP、IKE）。在网络层对 IP 数据包进行加密与认证，是 Site-to-Site VPN 的核心技术。              |
| **OSPF**        | **开放最短路径优先。** 基于链路状态（Link-State）的内部网关协议（IGP），使用 Dijkstra 算法计算自治系统（AS）内的最短无环路由树。封装在 IP 协议 89 中。       |

## 四、 网络接口层 (Network Access / Link Layer)

对应 OSI 模型的数据链路层与物理层（L2, L1）。处理硬件地址、物理媒介与帧的传输。

|**协议名称**|**核心功能与技术特征**|
|---|---|
|**ARP**|**地址解析协议。** （通常归类为 L2.5）。在同一广播域内，通过 IPv4 地址解析目标网卡的物理 MAC 地址。|
|**Ethernet (802.3)**|**以太网标准。** 有线局域网的主导标准。定义了 48 位 MAC 地址体系、帧格式规范以及 CSMA/CD（载波监听多路访问/冲突检测）媒体接入控制机制。|
|**Wi-Fi (802.11)**|**无线局域网标准。** 定义了无线电磁波的调制解调、信道划分以及 CSMA/CA（冲突避免）机制。|
|**VLAN (802.1Q)**|**虚拟局域网。** 在以太网帧中插入 4 字节的 VLAN Tag，通过逻辑隔离划分广播域，提升二层网络安全性与性能。|
|**PPP**|**点对点协议。** 用于同步或异步串行链路（如老式拨号、专线），提供身份验证（PAP/CHAP）和网络层协议复用。|
