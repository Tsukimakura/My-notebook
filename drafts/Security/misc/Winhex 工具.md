# Winhex 工具

当一个加密卷被解密并挂载为逻辑驱动器（Logical Drive）后，WinHex 解析的是该卷内部的**文件系统**（通常为 FAT32、NTFS 或 exFAT）。用户看到的视图是操作系统层面的文件目录结构与底层数据恢复信息的结合。

## 一、 `$` 开头的系统元数据文件 (NTFS Metafiles)

如果在 WinHex 中看到大量以 `$` 开头的文件（如 `$MFT`, `$Bitmap`, `$LogFile`），说明该卷使用的是 **NTFS (New Technology File System)** 文件系统。

这些文件通常对用户隐藏（Hidden/System 属性），但在 WinHex 等取证工具中可见。它们不是用户数据，而是**定义文件系统本身的数据**。

### 1. `$MFT` (Master File Table / 主文件表)

- **定义**：NTFS 卷的核心数据库。

- **功能**：卷上的每一个文件（包括 `$MFT` 自身）在表中都有一条记录。该记录存储了文件的所有属性：文件名、创建时间、权限、以及数据所在的物理位置（Data Runs）。

- **取证意义**：它是数据恢复的核心。如果文件被删除，系统只是在 `$MFT` 中将该文件的记录标记为“未使用”，数据往往仍保留在磁盘上。

### 2. `$Bitmap` (Cluster Allocation Bitmap / 簇位图)

- **定义**：一张巨大的位图，用于跟踪卷上簇的使用情况。

- **功能**：每一位（Bit）代表卷上的一个簇。`1` 表示被占用，`0` 表示空闲。

- **取证意义**：WinHex 依靠它来判断哪些空间是“空闲空间”（Free Space），这部分空间通常包含被删除文件的残留数据。

### 3. `$LogFile` (Journaling Log / 日志文件)

- **定义**：事务日志文件。

- **功能**：记录所有对元数据的更改（如创建文件、重命名）。用于系统崩溃后的快速恢复（回滚或重做操作）。

### 4. `$Volume`

- **功能**：包含卷标（Volume Label）和 NTFS 版本号。

## 二、 操作系统生成的系统文件夹

当加密卷被挂载到 Windows 系统时，操作系统会自动在卷根目录下创建辅助文件夹。这些不是加密容器自带的，而是**挂载环境**生成的。

### 1. `$RECYCLE.BIN` (或 `RECYCLER`)

- **定义**：Windows 回收站文件夹。

- **结构**：

    - 这是一个标准的文件夹，而非元数据文件。

    - 内部通常包含以用户 `SID`（安全标识符，如 `S-1-5-21...`）命名的子文件夹。

- **取证意义**：当用户在挂载的卷中删除文件时，文件首先被移动到这里，并被重命名（通常以 `$R` 开头是数据，`$I` 开头是原始路径信息）。

### 2. `System Volume Information`

- **定义**：Windows 系统还原和卷影复制服务（VSS）的存储目录。

- **内容**：可能包含系统还原点、索引服务数据库、分布式链接跟踪服务日志等。

- **取证意义**：即使在外部挂载的加密卷中，Windows 索引服务也可能扫描该卷并在其中创建索引文件，这可能泄露文件内容的关键词。

## 三、 删除标记与文件状态 (Deleted Files)

在 WinHex 的文件列表中，还会看到特定的删除状态标识，这涉及文件系统的删除机制。

### 1. 文件名首字符被替换 (如 `?rl.txt` 或 `σrl.txt`)

- **适用系统**：**FAT32 / exFAT**。

- **原理**：当 FAT 系统删除文件时，并不会抹去数据，而是将目录项（Directory Entry）中文件名的**第一个字节**修改为 `0xE5`（在 ASCII 扩展表中常显示为 `σ` 或在工具中显示为 `?`）。

- **含义**：这告诉系统“该文件名已废弃，其占用的空间可以被新数据覆盖”。

- **恢复**：只要数据区未被覆盖，只需将首字母改回原字符即可恢复文件。

### 2. 删除图标 / 灰色显示

- **适用系统**：**NTFS**。

- **原理**：NTFS 删除文件时，是在 `$MFT` 中将该文件的记录标志位从 `In Use` 改为 `Not In Use`。文件名通常保持完整。

- **WinHex 表现**：文件名前会显示一个带红叉的图标或问号图标，表明该文件已被逻辑删除。
