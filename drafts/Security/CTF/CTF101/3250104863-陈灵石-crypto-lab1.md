## 跳舞的小人

题名提示福尔摩斯的“跳舞的小人”，看上去也是单表替换密码。

圆点相当于原版的旗子，表示词尾。

手动给每一种不同姿势编号，按出现频率编号为 `A`、`B`、`C`……。




Codex 帮忙写了个解析图片到密文的脚本：

```python
from collections import Counter
from hashlib import sha1
from PIL import Image
import numpy as np
import string


IMAGE = "crypto_challenge1.png"
DOT_MAX_SIZE = 130  # 右上角小圆点的连通域面积上限


def get_runs(values):
    """把一维投影中的连续非零区间取出来。"""
    result = []
    start = None

    for i, value in enumerate(values):
        if value > 0 and start is None:
            start = i
        elif value == 0 and start is not None:
            result.append((start, i - 1))
            start = None

    if start is not None:
        result.append((start, len(values) - 1))

    return result


def connected_components(binary):
    """8 邻域连通域，不依赖 OpenCV。"""
    height, width = binary.shape
    visited = np.zeros(binary.shape, dtype=bool)
    components = []

    for y, x in zip(*np.where(binary)):
        if visited[y, x]:
            continue

        stack = [(y, x)]
        visited[y, x] = True
        component = []

        while stack:
            cy, cx = stack.pop()
            component.append((cy, cx))

            for dy in (-1, 0, 1):
                for dx in (-1, 0, 1):
                    ny, nx = cy + dy, cx + dx

                    if not (0 <= ny < height and 0 <= nx < width):
                        continue

                    if binary[ny, nx] and not visited[ny, nx]:
                        visited[ny, nx] = True
                        stack.append((ny, nx))

        components.append(component)

    return components


def glyph_signature(cell):
    """
    返回：
      signature: 去掉小圆点后的图形签名
      word_end: 该小人后是否有分词圆点
    """
    components = connected_components(cell)

    # 小圆点是一个独立且较小的连通域
    word_end = any(len(comp) <= DOT_MAX_SIZE for comp in components)

    # 保留真正的小人主体
    body = [comp for comp in components if len(comp) > DOT_MAX_SIZE]

    if not body:
        return None, False

    ys = [y for comp in body for y, _ in comp]
    xs = [x for comp in body for _, x in comp]

    min_y, max_y = min(ys), max(ys)
    min_x, max_x = min(xs), max(xs)

    normalized = np.zeros(
        (max_y - min_y + 1, max_x - min_x + 1),
        dtype=bool
    )

    for comp in body:
        for y, x in comp:
            normalized[y - min_y, x - min_x] = True

    # 相同图形会有相同的尺寸和像素布局
    data = normalized.tobytes() + str(normalized.shape).encode()
    signature = sha1(data).hexdigest()

    return signature, word_end


# 读取并二值化：黑色线条为 True
image = Image.open(IMAGE).convert("L")
pixels = np.array(image)
binary = pixels < 128

# 图中每列和每行小人之间均有空白，因此用投影直接切分
x_runs = get_runs(binary.sum(axis=0))
y_runs = get_runs(binary.sum(axis=1))

print(f"检测到 {len(x_runs)} 列、{len(y_runs)} 行")

symbols = []

for y1, y2 in y_runs:
    for x1, x2 in x_runs:
        cell = binary[y1:y2 + 1, x1:x2 + 1]
        signature, word_end = glyph_signature(cell)

        # 最后一行右侧是空白区域，跳过
        if signature is not None:
            symbols.append((signature, word_end))

# 按出现频率临时编号为 A、B、C……
counter = Counter(signature for signature, _ in symbols)
ordered = [signature for signature, _ in counter.most_common()]

label = {
    signature: string.ascii_uppercase[i]
    for i, signature in enumerate(ordered)
}

print(f"检测到 {len(label)} 种不同的小人姿势")

# 按右上角圆点恢复单词边界
words = []
current = []

for signature, word_end in symbols:
    current.append(label[signature])

    if word_end:
        words.append("".join(current))
        current = []

if current:
    words.append("".join(current))

ciphertext = " ".join(words)

print("\n提取到的密文：")
print(ciphertext)
```

## 维吉尼亚密码

先看加密脚本，字符表共 97 个字符，密钥长度是 15~29，密钥每个字符是字符表内除空格外的任意元素（1~96）。（剔除下标 0 防止解密时逆运算出问题）

加密不是标准的加法模运算，是乘法模运算。97 是素数，对所有 1~96 都存在乘法模逆元。解密公式为：$p_i = c_i \times K_{i \bmod L}^{-1} \bmod 97$，其中 $L$ 为密钥长度；只要恢复密钥即可。

先确定密钥长度：加密每隔 `L` 个字符重复使用同一个乘数。两段密文相隔 `L`，受到相同密钥元素加密，字符相同的概率会更高。

![[ctf101-crypto1-2.png]]

`29、58（29*2）` 出现相同字符的频率明显更高，结合密钥长度范围确定密钥长度为 29。

明文的所有空格（0）对应的密文也是空格。

按照密钥长度把密文分成 29 列，利用频率分析还原密钥：

![[ctf101-crypto1-3.png]]

key: `[51, 14, 22, 90, 67, 43, 17, 82, 48, 17, 41, 33, 89, 94, 60, 80, 13, 72, 79, 18, 65, 50, 20, 6, 36, 39, 56, 7, 65]`

## RSA

先理解一下加密代码：把 flag 当作一个大整数 `m`，取 `m` 右移 150 位后的下一个素数作为模数 `n`，再公布同一消息 `m` 在同一模数 `n` 下、多个不同指数的幂作为密文。

了解一下共模攻击，正常 RSA 要保证不同密文使用不同模数 n。如果 `c1 = m^e1 mod n; c2 = m^e2 mod n` 且 `gcd(e1, e2) = 1`，根据 Bezout 定理，存在 `a×e1 + b×e2 = 1`，于是

```text
m
= m^(a×e1 + b×e2)
= (m^e1)^a × (m^e2)^b
≡ c1^a × c2^b mod n
```

这样不用分解 n 也能恢复 m。

这道题

```python
"AAA😍".encode()
# b'AAA\xf0\x9f\x98\x8d'
# [65, 65, 65, 240, 159, 152, 141]
```

给出的密文实际是

```text
c65  = m^65  mod n
c240 = m^240 mod n
c159 = m^159 mod n
c152 = m^152 mod n
c141 = m^141 mod n
```

注意到， `gcd(65, 159) = 1`，利用扩展欧几里得算法求出 `a, b`： `9 × 159 - 22 × 65 = 1`

根据共模攻击的原理，就有：

```text
m
≡ m^(9×159 - 22×65)
≡ (m^159)^9 × (m^65)^(-22)  mod n
≡ c159^9 × inverse(c65^22, n) mod n
```

题目没有给出 `n` ，要先恢复模数。

`n` 一定整除

```python
d1 = c65**240 - c240**65
d2 = c65**159 - c159**65
```

计算 $n_0 = gcd(abs(d1), abs(d2))$，$n_0$ 是 $n$ 的倍数，取 $n_0$ 的大素因子就是 $n$。

通过共模攻击恢复 m (mod n)，由于 `n = nextprime(m >> 150)`，显然 `m > n`，根据题意， `prevprime(n) <= (m >> 150) < n`，即 `prevprime(n) × 2^150 <= m < n × 2^150`，以此筛出 `m = m(mod n) + k*n` 中的 k，再把大整数重新转为字符串即可得到明文。

![[ctf101-crypto1-5.png]]

flag: `AAA{C0mM0n_m0dUlUs_4tt4ck_1s_1nt3r3st1ng}`

```python
from math import gcd
from sympy import factorint, nextprime, prevprime

# "AAA😍".encode() = [65, 65, 65, 240, 159, 152, 141]
c = {
    65: 62672938275009705596581242847130514775891540954531116,
    240: 28065112754348826692839224620054962177237340625508142,
    159: 82805428369361023445247061843917815511685788893461488,
    152: 64529102835595887450014112173830620877278761152089439,
    141: 61692909713449333722171394128578104844776919632656810,
}

def same_power_difference(e1, e2):
    """返回必被 n 整除的 |c[e1]^e2 - c[e2]^e1|。"""
    return abs(pow(c[e1], e2) - pow(c[e2], e1))

# 恢复 n 的候选倍数。
# 两个关系都含 n；gcd 会消去大部分无关因子。
d1 = same_power_difference(65, 240)
d2 = same_power_difference(65, 159)
g = gcd(d1, d2) # n0

print("gcd factors:", factorint(g))

# 取唯一的大素因子。
n = max(factorint(g))
print("n =", n)

# 共模攻击。
# 9 * 159 - 22 * 65 = 1
m_mod_n = pow(c[159], 9, n) * pow(pow(c[65], 22, n), -1, n) % n

# 利用 n = nextprime(m >> 150) 将 m 从模 n 的剩余类提升回来。
B = 1 << 150  # 2^150
low = prevprime(n) * B
high = n * B

# low <= m_mod_n + k×n < high
first_k = (low - m_mod_n + n - 1) // n
last_k = (high - 1 - m_mod_n) // n

for k in range(first_k, last_k + 1):
    m = m_mod_n + k * n
    if nextprime(m >> 150) != n:
        continue
    if not all(pow(m, e, n) == value for e, value in c.items()):
        continue

    flag = m.to_bytes((m.bit_length() + 7) // 8, "big")
    print("flag =", flag)
    break
```

## 零知识证明

“零知识”代表  Verifier 无法得知关于秘密本身的有效信息。零知识证明就是在这个前提上，Prover 要向 Verifier 证明自己直到秘密。课上讲的 Schnorr 协议中，公开了大素数 p（模数）、生成元 g 和 y = g^x (mod p)，验证者通过与证明者按标准顺序的信息交换，结合公开信息进行验证。和非对称加密类比一下，秘密 x 就相当与私钥，根据私钥生成，且难以反向还原的 y 就相当与公钥，有点像验证签名？

细致分析一下 Schnorr 协议，第一步先由 Prover 发送随机的承诺，t 参与后续验证，相当于保证这个 t 无法通过还未得知的挑战 c 刻意构造。然后再由 Verifier 发送随机的挑战。Prover 结合 c 和 x，一方面“完成挑战”，一方面添加 x 的信息用于验证，r+cx 通过一开始的随机 r 掩盖 x 的信息，保证“零知识”性。（一开始发送 t=g^r 应该除了后续指数运算验证之外，还有 r 难以还原的考量？）验证就通过“公钥” y 和通信中的信息比对。

Schnorr 协议是基于数论的。一下列举一种基于图论的：

图 $G_1$ 和 $G_2$ 同构，秘密 $\pi$ 是 $G_1$ $G_2$ 的映射关系。找出 $\pi$ 是 NP 困难问题。

1. 承诺： Prover 根据 $G_1$ 随机生成另一个通过图 $H$，则  Prover 同时拥有了 $G_1 \rightarrow H$ 和 $G_2 \rightarrow H$ 的映射。把 $H$ 发给 Verifier。
2. 挑战： Verifier 提出两个要求中的一个
    	1. 挑战 0： $G_1 \rightarrow H$ 的映射
    	2. 挑战 1： $G_2 \rightarrow H$ 的映射
3. 响应： Prover 根据挑战发送映射表。
4. 验证：核对是否能够完成 $G_1$ 或 $G_2$ 到 H 的转换。

- 重复 100 次，每次重新生成随机图  $H$

根据零知识证明的三大特性：

1. 完备性： Prover 再任何情况（任意 $H$，任意两个挑战之一）下都能透过验证
2. 可靠性： 假设 Prover 不知道 $\pi$ ，再承诺时生成 $H$ 后最多知道 $G_1 \rightarrow H$ 和 $G_2 \rightarrow H$ 的映射中的一个。挑战由 Verifier 随机提出，每轮只有 1/2 概率能够通过验证。 100 轮通过的概率 $(1/2)^{100}$ 可以忽略。
3. 零知识性： 由于每次的 $H$ 都是重新随机生成的，挑战只提出一个，Verifier 无法得知 $G_1 \rightarrow G_2$ 的映射关系。
