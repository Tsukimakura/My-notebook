```python
#!/usr/bin/python3
# 指定解释器，使 python 能作为脚本直接被执行

data = input("give me your string: ")
# 控制台显示 “give me your string: ” 并等待用户输入，把输入结果用 data 保存
data_new = ""
# 一个空字符串
for d in data:
# 遍历输入字符串中的每一个字符
	if d in 'abcdefghijklmnopqrstuvwxyz':
	# 如果当前访问的字符是小写字母
		data_new += chr(ord(d) - 32)
		# 在 data_new 后拼接一个字符，为当前访问字符的 Unicode 码点减去 32 后代表的字符
		# 即把小写字母转换成大写
	elif d in 'ABCDEFGHIJKLMNOPQRSTUVWXYZ':
	# 否则判断如果当前字符是大写字母
		data_new += chr(ord(d) + 32)
		# 在 data_new 后拼接一个字符，为当前访问字符的 Unicode 码点加上 32 后代表的字符
		# 即把大写字母转换成小写
	else:
		data_new += d
		# 否则直接把当前字符拼接到 data_new 最后

print("now your string:", data_new)
# 把经过以上过程后的 data_new 字符串打印出来
```

 **解题流程：**

- 在源码最后补充 512 字节对齐代码：`times 510-($-$$) db 0`。（留两字节给魔数）
	- `$`: 当前指令地址
	- `$$`: 当前段起始地址

- 补充 BIOS 引导魔数：`dw 0xAA55`。（小端序）

- 使用 `nasm -f bin code.asm -o boot.bin -l boot.lst`，生成  flat binary 二进制文件（无头部），同时生成包含相对内存偏移量的 `.lst` 导航文件，便于后续精确下断点。

- 启动模拟器并挂起 CPU：`qemu-system-i386 -fda boot.bin -s -S`。

	（把 boot.bin 当作这台虚拟机的 “软盘 A 驱动器” 插入。)
	（BIOS 启动时会按照固定的顺序（通常是软盘 -> 硬盘 -> 光驱）去寻找包含 `0xAA55` 魔数的引导扇区。挂载为 `-fda` 确保 BIOS 一通电就能找到并加载代码。）
	（`-s`：`-gdb tcp::1234` 的简写。让 QEMU 在后台的 1234 端口 开启一个 GDB 调试存根（GDB stub）服务器。）
	（`-S`：在启动时冻结CPU，停在加电后的第一条指令处。）

- 使用 `gdb --nx` 启动无插件 GDB。（pwndbg 不支持调试 16 位裸机程序）

- 连接并设定为 16 位架构：`target remote localhost:1234`，`set architecture i8086`。

- TUI 分屏：`layout asm` 和 `layout regs`。

- `hb *0x7c00` 在程序载入处下硬件断点。（BIOS 把 Bootloader 固定加载到 `0x7c00`，由于此时因为 `-S` 还停在最开始的位置，没有加载 Bootloader，软件端点会导致 `0xcc` 被载入的程序覆盖，断点消失。）

- 通过查 `.lst` 文件，计算出目标指令的绝对物理地址（如：基址 `0x7C00` + 偏移 `0x24` = 绝对地址 `0x7C24`），分别下断点并在断点处单步执行，在寄存器窗口查看寄存器中的值，得到答案。

```python
def xgcd(a, b):
    x1, y1, x2, y2 = 1, 0, 0, 1
    while(b != 0):
        q = a // b
        r = a % b

        t = x1
        x1 = x2
        x2 = t - q * x2

        t = y1
        y1 = y2
        y2 = t - q * y2

        a = b
        b = r

    return a, x1, y1
```

## Web

### 思考题

**在浏览器中输入网址到最后看到网页，这个过程中发生了什么？**

浏览器先提取 URL 中的协议（HTTP/HTTPS）、域名、端口、路径、查询参数等信息；（检查本地 HSTS，匹配的话把 HTTP 强转为 HTTPS）；浏览器查找本地与该域名对应的 Cookie，准备在后续请求头中携带。

然后进行 DNS 解析 -- 最坏的情况下依次查询浏览器、操作系统、路由器和 ISP 的 DNS 缓存都没有查询到，再依次查询根域名服务器、TLD 域名服务器、权威域名服务器，把获得的记录（如 A、AAAA、CNAME等）返回从操作系统写入缓存。

操作系统获取到目标 IP 后通过子网掩码判断是否在同一局域网内。如果相同可以直接在局域网内通过 ARP 得到目标 MAC 地址直接物理通信。否则需要把数据发给路由器（网关）（也是通过局域网内广播 ARP 请求，得到单个 MAC 地址应答）。

浏览器底层 Socket 通过目标 IP 和端口发起 TCP 连接（三次握手），如果是 HTTP 再进行一次 TLS 握手。

报文多层封装 -- 应用层构建 HTTP 请求报文，然后给应用层和传输层间的 TLS 层加密，传输层添加 TCP 头部（源端口、目标端口、序列号），网络层添加 IP 头部（源局域网 IP + 目标公网 IP），链路层添加 MAC 头部和尾部发出。

数据包发到路由器后路由器进行 NAT，替换为公网 IP，然后在公网路由器之间传输（通过 OSPF 等路径优化算法，每个节点剥离源 MAC 并重写）

如果目标服务器由反代（如 Nginx），则到达 Nginx 节点完成 TCP 连接，反代执行 TLS 卸载、解密、解析、内网转发等等操作。然后业务服务器处理 HTTP 请求，提取 Cookie 中的 Session ID，执行业务逻辑，再构建 HTTP 响应报文按相同方式返回。

浏览器接收到最后经过 TLS 解密的 HTML 字节流，再浏览器前端渲染页面（构架 DOM tree、CSSOM tree、Render tree  然后绘制合成）。

最后如果超时没有数据传输，经过 TCP 四次挥手释放连接。

Request Headers:

- **`host: www.baidu.com`**

    目标主机的域名， HTTP/1.1 协议中唯一必须携带的请求头。

- **`connection: keep-alive`**

    保持连接。便于后续拉取图片、JS 、CSS 文件等。

- **`user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/150.0.0.0 Safari/537.36`**

    操作系统、浏览器内核等数据。

- **`sec-ch-ua: "Not;A=Brand";v="8", "Chromium";v="150", "Google Chrome";v="150"`**

	现代身份标识。基于 Chromium 150 的 Google Chrome。`"Not;A=Brand"` 用来防止服务器代码只适配特定浏览器。

- **`sec-ch-ua-mobile: ?0`**

    `?0` 代表 False。表示不是移动设备，显示电脑版网页。

- **`sec-ch-ua-platform: "Windows"`**

    操作系统是 Windows。

- **`accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,image/apng,*/*;q=0.8...`**

    浏览器支持接收的数据格式及其优先级。排在前面的最优先（HTML 网页），支持现代图片格式（avif, webp），`*/*;q=0.8` 表示任意内容，但优先级只有 0.8。

- **`accept-encoding: gzip, deflate, br, zstd`**

    支持的网页压缩算法。

- **`accept-language: zh-CN,zh;q=0.9,en;q=0.8`**

    语言偏好。首选简体中文 (`zh-CN`)，其次是普通中文 (`zh`)，最后是英文 (`en`)。服务器据此返回对应语言的页面。

以 `sec-fetch-` 开头的现代安全请求头，用于防范跨站请求伪造 (CSRF) 等攻击。

- **`sec-fetch-dest: document`**

    表示这次请求是为了拉取一个 HTML 文档（即主网页）。

- **`sec-fetch-mode: navigate`**

    请求模式。表示这是一次页面导航（页面跳转、刷新或直接输入网址打开）。

- **`sec-fetch-site: none`**

    请求来源。`none` 表示这个请求没有来源网站。

- **`sec-fetch-user: ?1`**

    `?1` 代表 True。表示这次网络请求是由用户主动触发的。

- **`upgrade-insecure-requests: 1`**

    支持 HTTPS。把 HTTP 页面（如果是），重定向到 HTTPS 版本。

- **`cache-control: max-age=0`**

    缓存控制。通常在刷新页面或在地址栏敲回车时产生。忽视缓存重新从服务器获取数据。

- **`cookie: __bid_n=... BAIDUID=...`**

    Cookie。

`IDM` 的原理是多线程并行下载，最后合并，比原本单线程下载快数倍。实现方式是先向服务器请求（`HEAD`）文件大小和是否支持范围请求（`Ranges`）。如果支持，比如服务器返回 `Accept-Ranges: bytes`，则把文件均匀切分，多线程分别请求不同块的文件数据（如 `Range: bytes=0-1023`）。最后合并各个分块。不支持断点续传就不行，因为断点续传也依赖范围请求功能，不支持断点续传通常是因为不支持范围请求功能。

SQL 注入大概就是把用户输入直接当作 SQL 语句执行，导致执行了非预期的业务逻辑，使攻击者实现相应目的。ORM 实现封装，直接调用相应语言中的方法，避免手写 SQL 的漏洞。ORM 实现参数化查询，把语句结构和数据分开发送给数据库，数据不会被当作代码执行。同时通常对输入数据强制校验数据类型，比如整型数据就无法输入恶意字符串。

SQL 注入的是 SQL 代码，主要攻击后端数据库；XSS 注入的是 JS 代码，主要攻击浏览器前端，比如窃取用户会话、伪造请求、客户端钓鱼等。他们的根本都是信任用户输入，并把用户输入的数据当作代码执行。

侧信道攻击就是不通过实际的业务逻辑漏洞，而是通过计算机处理特定数据（如密钥、密码等）时的其它效果（大部分时候是物理信息，如耗时、功耗、电磁辐射、声音等）来反推数据。

**Timing 侧信道：**

-  C 语言 `strcmp() memcmp()` Java `String.equals()` python `==` PHP `== / ===` 由于这些比较采用短路逻辑，比较字符串时逐字节比对，不匹配立刻停止。可以通过一个个字符尝试，统计微小时间差测试出答案。

- SQL 注入的时间盲注， 如 `SELECT * FROM users WHERE id = 1 AND IF(ASCII(SUBSTRING(password, 1, 1)) = 83, SLEEP(5), 0);` 对每个字符逐个判断，可通过延时判断是否正确。 `sleep()` 可以替换成其它耗时操作，如笛卡尔积、复杂正则匹配/加密运算等等。

- 密码学方面，早期 RSA 实现处理二进制 `1` `0` 的乘法耗时不同。AES 频繁访问 S-box，相应内存地址处被加载到 Cache（速度更快），攻击者通过测试访问特定内存的速度，推断加密算法刚刚访问的数据，从而还原相关数据。

- 防御方法可以使用大部分语言提供的常量时间的安全函数，或无论运行结果统一响应时间等等。

## Pwn

### 源码漏洞分析

1. `get_heart_beat` 函数中的 `fread(tmp->data, tmp->size - sizeof(struct hbpkt), 1, stdin);`： 前面代码检查了 `tmp->size > 0x1000`，但没有检查 tmp->size 的下界，导致 `tmp->size - sizeof(struct hbpkt)` 下溢为极大正数。此时 `fread` 尝试向 `buffer`（仅 `0x1000` 字节大小）写入大量数据，造成栈溢出，会覆盖返回地址，导致控制流紊乱/被劫持，可能导致程序段错误崩溃或执行被写入/覆盖的恶意代码。

2. `get_heart_beat` 中的 `strlen(tmp->data)` 以及 `reply_heart_beat` 中的 `fwrite(pkt, 1, pkt->size, stdout);`：real_size 和结构体 size 字段的值可能不同。由于 `strlen()` 会零截断，如果构造一个包，在结束前发送 `\0`。`malloc` 实际只分配了比实际更少的堆块。进入 `reply_heart_beat` 打印时，程序调用 `fwrite` 读取堆上的数据，会泄露 `res` 堆块之后相邻的堆内存数据，导致敏感信息泄露。

3. `main` 函数中的 `if (err) { free(p); continue; }`：当 `reply_heart_beat` 成功执行并返回 `0` 时，`if(err)` 不成立，循环直接进入下一次，丢失了堆指针 `p`，且未调用 `free(p)` 导致内存泄露。

4. `reply_heart_beat` 函数中的 `int err;` 和 `int written;`，如果传入的 `pkt->size` 为 `0`，`if (pkt->size)` 不满足，`written` 不会被赋值。在 `if (written == 0 || written != pkt->size)` 中使用了未初始化的 `written`，且 `err` 也没有默认值。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <stdbool.h>

struct hbpkt
{
    uint32_t size;
    uint32_t timestamp;
    uint32_t index;
    uint32_t cred;
    char data[];
};

struct hbpkt *get_heart_beat()
{
    uint8_t buffer[0x1000] = {0};
    fread(buffer, sizeof(struct hbpkt), 1, stdin);
    struct hbpkt *tmp = (struct hbpkt *)buffer;
    // 增加下限检查，防止 tmp->size - sizeof(struct hbpkt) 发生整数下溢
    if (tmp->size < sizeof(struct hbpkt) || tmp->size > 0x1000)
        return NULL;
    fread(tmp->data, tmp->size - sizeof(struct hbpkt), 1, stdin);
    // 直接使用网络包指定的大小 tmp->size 防止越界访问
    struct hbpkt *res = malloc(tmp->size);
    if (!res)
        return NULL;

    memcpy(res, buffer, tmp->size);
    res->index += 1;
    return res;
}

int reply_heart_beat(struct hbpkt *pkt)
{
    // 初始化变量
    int err = 0;
    size_t written = 0;
    if (pkt->size)
    {
        written = fwrite(pkt, 1, pkt->size, stdout);
        fflush(stdout);
    }

    if (written == 0 || written != pkt->size)
    {
        err = -1;
    }

    return err;
}

int main()
{
    while (true)
    {
        struct hbpkt *p = get_heart_beat();
        if (!p)
            break; // 避免死循环死锁
        reply_heart_beat(p);
        // 不管成功失败都释放堆内存，防止内存泄漏
        free(p);
    }
    return 0;
}
```
